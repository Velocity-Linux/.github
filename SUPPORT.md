# Support

## Documentation

The first place to look for help is the official documentation:

- **Documentation**: https://docs.velocityos.org
- **Installation Guide**: https://docs.velocityos.org/install
- **Configuration Reference**: https://docs.velocityos.org/configuration
- **Troubleshooting**: https://docs.velocityos.org/troubleshooting

The documentation includes step-by-step guides, configuration references, and troubleshooting articles.

## Discussions

For questions, ideas, and community support, use GitHub Discussions:

- **General Discussion**: https://github.com/orgs/Velocity-Linux/discussions
- **Show and Tell**: Share your Velocity OS setup and customizations
- **Q&A**: Ask configuration and usage questions

Discussions are the best place for open-ended questions and community interaction.

## Bug Reports

If you have found a bug:

1. Search existing issues to avoid duplicates.
2. Use the [Bug Report](https://github.com/Velocity-Linux/.github/blob/main/.github/ISSUE_TEMPLATE/bug_report.yml) issue template.
3. Include version information, hardware details, steps to reproduce, and relevant logs.

See [CONTRIBUTING.md](CONTRIBUTING.md#bug-reporting) for details.

## Security Reports

**Do not report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability, please report it privately:

- **Email**: velocityos@tutamail.com
- **PGP key**: https://keys.openpgp.org/search?q=velocityos@tutamail.com

See [SECURITY.md](SECURITY.md) for the full security policy.

## Feature Requests

Feature requests and proposals are welcome:

1. Use the [Feature Request](https://github.com/Velocity-Linux/.github/blob/main/.github/ISSUE_TEMPLATE/feature_request.yml) issue template.
2. Describe the problem, proposed solution, alternatives, and trade-offs.
3. For large features, start a Discussion to gather feedback before opening an issue.

See [CONTRIBUTING.md](CONTRIBUTING.md#feature-proposals) for guidance.
